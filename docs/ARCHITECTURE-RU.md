# Архитектура

## Компоненты на eMotion

Основной пакет `org.brailleemotion.appmanager` содержит интерфейс и всю пользовательскую логику. Он работает как обычное приложение Android и использует только публичные системные Intent и API.

Мост `com.selvashc.shortcut.appmanager` нужен для совместимости с заводским меню. Его единственная Activity запрашивает у Android запускаемый Intent основного пакета, открывает его и сразу завершает работу. Если диспетчер отсутствует, пользователь получает короткое сообщение. Мост генерируется скриптом из шаблона; закрытый код изготовителя в него не входит.

## Основное Android-приложение

`MainActivity` строит экраны из стандартных Android-компонентов и управляет фокусом. Списки создаются заново при открытии раздела, поэтому новые и удалённые приложения появляются без ручного редактирования ярлыков.

`ApkRepository` просматривает только файлы с расширением APK непосредственно в общей папке Download, извлекает сведения о пакете и отбрасывает файлы, которые PackageManager не может разобрать.

`ApkInstaller` копирует выбранный файл в закрытый кэш, повторно проверяет пакет и версию, затем выдаёт временный URI только на чтение через `ApkInstallFileProvider`. Установку завершает системный Package Installer. Приложение не обладает привилегией тихой установки.

`HelpContent` формирует оглавление и абзацы русской справки. Каждый абзац — отдельный фокусируемый элемент, поэтому длинный текст не отправляется скринридеру одной репликой.

## Разрешения Android

- `QUERY_ALL_PACKAGES` нужен для полного автоматического списка запуска и удаления;
- `REQUEST_DELETE_PACKAGES` открывает системное подтверждение удаления;
- `READ_EXTERNAL_STORAGE` используется только на Android 8–10;
- `MANAGE_EXTERNAL_STORAGE` даёт Android 11+ возможность найти APK в Download;
- `REQUEST_INSTALL_PACKAGES` разрешает передать APK системному установщику.

В манифесте нет доступа к интернету, контактам, камере, микрофону и местоположению. `ApkInstallFileProvider` не экспортируется и принимает только URI временной внутренней копии.

## Windows-установщик

`braille_emotion_installer.py` выбирает графический либо служебный CLI-режим. `installer_gui.py` управляет окном, фокусом, доступными действиями и фоновыми операциями. `installer_view.py` содержит модели представления, `help_content.py` — русскую справку Windows-программы.

`adb_client.py` запускает только вложенный ADB и обращается к одному выбранному serial. `installer_core.py` проверяет ресурсы, определяет модель и состояние пакетов, выполняет установку или удаление и повторно проверяет результат. `installer_errors.py` переводит технические сбои в понятные категории и способы исправления.

Ожидаемые SHA-256 хранятся отдельно в `resource_hashes.py`. При сборке они генерируются по реальному payload, что защищает от случайной подмены одного из вложенных файлов.

## Определение состояния

Состояние зависит только от двух пакетов:

- основной пакет есть и мост есть — установлено полностью;
- найден один из них — установлено частично;
- оба отсутствуют — не установлено.

Перед изменением проверяются модель `B340` или системное имя с признаком Braille eMotion, состояние ADB и число подключённых устройств. При неоднозначности операция останавливается.

## Границы безопасности

Проект не предоставляет root-доступ и не записывает системные разделы. Это снижает риск, но не делает сторонний APK безопасным. Проверка структуры и подписи не заменяет проверку происхождения приложения.

Защитный фильтр удаления в Android-приложении уменьшает вероятность удаления заводского пакета, но не знает ценности пользовательских данных. Поэтому перед удалением остаются собственное предупреждение диспетчера и обязательное системное подтверждение Android.
