# Проверка перед выпуском

## Автоматические проверки

Из подготовленного Python-окружения запустите:

```powershell
$env:PYTHONPATH = (Resolve-Path .\windows-installer\src)
$env:QT_QPA_PLATFORM = 'offscreen'
.\.build-venv\Scripts\python.exe -m unittest discover `
  -s .\windows-installer\tests -v
```

Тесты проверяют разбор вывода ADB, состояния подключения, установку и удаление пакетов, проверку SHA-256, сообщения об ошибках, доступные имена элементов PyQt5, порядок Tab, диалоги и сохранение фокуса.

После сборки скрипт автоматически запускает EXE в режиме `bundle-check`. Отдельно повторите эту проверку из другой рабочей папки: так обнаруживается случайная зависимость от исходного каталога.

## Проверка Android APK

Через `apksigner verify --verbose --print-certs` убедитесь, что оба APK подписаны и схема подписи принимается Android. Через `aapt dump badging` проверьте пакет, версию, минимальный и целевой API. Через `aapt dump permissions` сравните разрешения с манифестом.

Установите сборку на тестовый B340 и проверьте:

- первый пункт получает фокус и произносится после запуска;
- стрелки проходят весь список из десятков приложений, а не первые пять строк по кругу;
- Home, End, Page Up, Page Down, Enter, пробел, Back и Escape работают ожидаемо;
- после установки нового APK список запуска обновляется;
- в списке удаления нет системных пакетов, SELVAS/HIMS, оболочки и самого диспетчера;
- предупреждения начинаются с безопасной кнопки «Отмена»;
- справка читается по одному абзацу;
- «Выйти» возвращает в заводское меню;
- после системной установки или удаления произносится фактический результат.

Проверьте пустые списки, повреждённый APK, большой APK, недостаток свободного места, отказ в специальных разрешениях и возврат из системных настроек.

## Проверка Windows-интерфейса

Включите NVDA или другой Windows-скринридер и выполните полный круг Tab и Shift+Tab. У каждого элемента должны быть имя, роль и понятное состояние. Фокус не должен исчезать после обновления устройства, завершения фоновой операции и закрытия диалога.

Проверьте масштаб Windows 100, 150 и 200 процентов, узкое окно и системную светлую/тёмную тему. Текст не должен обрезаться до потери смысла; журнал и длинная справка должны прокручиваться с клавиатуры.

Отдельные сценарии подключения:

- устройство отсутствует;
- USB-отладка не подтверждена;
- устройство `offline`;
- подключены два ADB-устройства;
- подключён обычный Android-телефон;
- B340 без компонентов;
- установлен только основной пакет;
- установлен только мост;
- установлены оба пакета.

Кнопки установки и удаления должны соответствовать именно двум пакетам проекта. Наличие или отсутствие RuStore не меняет результат.

## Полный цикл на устройстве

На тестовом устройстве, где сохранены нужные данные:

1. удалите оба компонента через EXE;
2. убедитесь, что статус изменился на «не установлен»;
3. установите набор тем же EXE;
4. убедитесь, что статус изменился на «установлен»;
5. откройте ярлык из заводского меню;
6. установите тестовый APK из Download через диспетчер;
7. запустите и удалите тестовое приложение;
8. повторно откройте диспетчер и проверьте обновление списков.

Не используйте для этой проверки устройство с единственной копией важных данных.

## Чистая Windows

Готовый EXE нужно проверить на компьютере без Python, Android Studio и ADB в `PATH`. Достаточно обычной 64-разрядной Windows 10 и Windows 11. Проверяются запуск, распаковка onefile, отображение кириллицы, встроенный ADB, отсутствие консольного окна и завершение дочернего ADB-сервера.

Если отдельных физических компьютеров нет, используйте чистые виртуальные машины для запуска и интерфейса. Проброс USB в виртуальную машину не всегда надёжен, поэтому итоговую установку всё равно проверьте на реальном ПК и B340.

## Проверка состава репозитория

Перед публикацией выполните `git status`, просмотр всех подготовленных файлов и поиск секретов. В истории не должно быть keystore, токенов, серийного номера устройства, личных путей, журналов, заводских APK, прошивки и результатов декомпиляции.

Бинарные релизные файлы не коммитятся. Они прикрепляются к GitHub Release вместе с `SHA256SUMS.txt`.
